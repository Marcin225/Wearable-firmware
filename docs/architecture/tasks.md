# FreeRTOS Tasks

The firmware uses two FreeRTOS tasks with different priorities to separate time-sensitive sensor acquisition from signal processing.

## Task Priorities

| Task | Priority | Main role |
| :--- | ---: | :--- |
| `vCollectAndFilterDataTask` | 2 | Sensor acquisition and preprocessing |
| `vCalculateVitalsTask` | 1 | HR and SpO2 calculations |

The collector task has higher priority because sensor data must be read before the hardware FIFO can overflow. The calculation task can be temporarily preempted when a new sensor batch becomes available.

## Collector Task Scheduling

`vCollectAndFilterDataTask` remains blocked and waits for a task notification.

The notification is generated by the MAX30102 interrupt handler when a new FIFO batch is available:

```text
MAX30102 interrupt
        ↓
task notification
        ↓
Collector Task wakes
        ↓
sensor data acquisition
        ↓
task blocks again
```

## Buffer Synchronization

Two measurement buffers are shared between the collector and calculation tasks.

When the collector fills a 256-sample buffer, a pointer to that buffer is sent through `fullQueue`. The collector then receives another available buffer from `emptyQueue`. 

After the calculation task finishes processing a buffer, its pointer is returned to `emptyQueue` so the buffer can be reused. This ensures that both tasks never use the same measurement buffer at the same time.

## Measurement Sessions

Each measurement buffer contains a `sessionId` identifying the continuous measurement session it belongs to.

Before using a received buffer, the calculation task compares its session ID with the current `measurementSessionId`. Outdated buffers are returned without being processed.

When the first buffer from a new session is received, the processing window and algorithm state are reset before the new data is added.

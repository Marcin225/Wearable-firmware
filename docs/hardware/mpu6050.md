# MPU6050-Compatible Motion Sensor

The prototype uses an IMU module sold as an **MPU6050-compatible sensor**. It provides three-axis acceleration data used for motion analysis and low-power wake-up.

The module communicates with the ESP32-C3 through I2C using the address `0x68`.

## Sensor Identification

A standard MPU6050 normally returns `0x68` from the `WHO_AM_I` register.

The module used in this prototype returns:

```text
WHO_AM_I = 0x98
```

Its register behavior, particularly the Wake-on-Motion configuration, matches the ICM-20689 more closely. The module is therefore treated as an ICM-20689 or ICM-20689-compatible clone where required.

The existing MPU6050 driver name is retained because the module was originally purchased and integrated as an MPU6050-compatible device.

## Accelerometer Configuration

Only the accelerometer is used by the production firmware. The gyroscope axes are disabled to reduce power consumption.

The normal measurement configuration is:

| Parameter | Configuration |
| :--- | :--- |
| Accelerometer axes | X, Y, Z |
| Sampling rate | 100 Hz |
| Full-scale range | ±2 g |
| DLPF bandwidth | 44.8 Hz |
| Gyroscope | Disabled |
| Temperature sensor | Disabled |
| FIFO | Accelerometer only |

Each accelerometer sample contains three signed 16-bit values:

```c
struct MpuSample {
    int16_t accX;
    int16_t accY;
    int16_t accZ;
};
```

## FIFO Acquisition

Accelerometer samples are collected in the hardware FIFO and read in batches.

Only accelerometer data is enabled in the FIFO, so each sample contains:

```text
AccX: 2 bytes
AccY: 2 bytes
AccZ: 2 bytes
--------------
Total: 6 bytes
```

The driver checks the current FIFO byte count, determines the number of available samples, and transfers them over I2C in batches. The samples are then stored in a local 256-sample ring buffer.

## Synchronization with PPG

The accelerometer and MAX30102 both operate at a nominal sampling rate of 100 Hz, but their samples are acquired independently.

When a new MAX30102 batch is processed, the available accelerometer samples are first collected into a temporary batch.

The accelerometer values are then interpolated to the positions of the PPG samples in that batch. This provides aligned AccX, AccY and AccZ values for each IR and RED sample before signal preprocessing.

## Motion Artifact Detection

The three accelerometer channels are used to estimate motion occurring during PPG acquisition.

After alignment and preprocessing, AccX, AccY and AccZ are included in the same processing window as the optical signals.

Their frequency content is used by the heart-rate algorithm to identify spectral components that may originate from movement rather than the pulse signal. The accelerometer therefore helps reduce the influence of motion artifacts on heart-rate estimation.

## Wake-on-Motion

The accelerometer is also used to wake the device from deep sleep.

Because the module behaves like an ICM-20689, Wake-on-Motion is configured using ICM-20689-compatible registers.

The wake configuration uses:

| Parameter | Configuration |
| :--- | :--- |
| Motion threshold | 300 mg per axis |
| Accelerometer sampling rate | 50 Hz |
| Motion detection | X, Y and Z |
| Interrupt polarity | Active low |
| Interrupt mode | Latched |
| Low-power accelerometer cycle | Enabled |

Motion detection compares the current accelerometer sample with the previous sample. When the configured motion threshold is exceeded, the IMU generates an interrupt that wakes the ESP32-C3 from deep sleep.
